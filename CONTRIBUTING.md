# Contributing to PrKit-Vue

Thanks for your interest in contributing to PrKit! Contributions, bug reports, and improvements are welcome.

## Getting Started

Before contributing, please review the existing code and check whether the issue or feature is already being addressed.

## Reporting Issues

If you find a bug or have a feature request, please open an issue in the [PrKit-Vue issue tracker](https://github.com/getprkit/vue/issues).

When reporting a bug, include:

- Your browser and environment.
- Steps to reproduce the issue.
- Expected and actual behavior.
- The affected PrKit version.

## Pull Requests

1. Fork the repository.
2. Create a feature branch from `prkit-vue`.
3. Keep changes focused and consistent with the existing codebase.
4. Test your changes before submitting.
5. Open a pull request targeting the `prkit-vue` branch.

## Commit Message Convention

PrKit-Vue follows the Vue-style commit message convention.

Commit messages should follow this format:

`type(scope): subject`

Examples:

- `feat(accordion): add multiple selection support`
- `fix(theme): correct inverse background colors`
- `refactor(css): migrate Less functions to native CSS`

Supported types:

- `build:` Changes that affect the build system or external dependencies.
- `chore:` Maintenance tasks and other changes that don't fit other categories.
- `ci:` Changes to CI configuration files and scripts.
- `docs:` Documentation-only changes.
- `feat:` A new feature.
- `fix:` A bug fix.
- `perf:` A code change that improves performance.
- `refactor:` A code change that neither fixes a bug nor adds a feature.
- `revert:` Reverts a previous commit.
- `style:` Changes that do not affect the meaning of the code (whitespace, formatting, etc.).
- `test:` Adding missing tests or correcting existing tests.

## Versioning

PrKit-Vue follows [Semantic Versioning (SemVer)](https://semver.org/).

Each release documents the corresponding upstream UIkit version.
